Read before relying

Know what the machine does.

Entropy Racer is intentionally inspectable. The game is the visible layer; the security model, limitations, and exact cryptographic stages matter more.

What is a Bitcoin seed phrase?

A BIP39 mnemonic is a human-readable representation of entropy plus a checksum. Wallet software uses it to derive keys. Possession of the words can allow control of the wallet, so treat them like the funds themselves.

What is entropy?

Entropy is unpredictable input. Strong wallet generation needs input an attacker cannot feasibly guess. Humans are generally poor randomness generators, which is why the system cryptographic random source is foundational here.

Why collect driving movement?

Key transitions, high-resolution timing, frame jitter, position, velocity, steering, firing, and collisions form a deterministic binary transcript that is hashed as a supplemental source. Entropy Racer does not claim each action contributes a fixed number of entropy bits. The percentage shown is only a collection threshold.

What is WebCrypto?

crypto.getRandomValues() is the browser's cryptographically secure pseudorandom generator interface and normally draws from operating-system randomness. It is not described here as guaranteed “true randomness.” If WebCrypto is unavailable or self-tests fail, generation is disabled with no fallback to Math.random().

What is physical entropy?

Coin flips and fair dice can contribute a conceptually independent source. Heads and tails map to one bit. Die results 1–4 map to two bits; 5 and 6 are rejected to avoid modulo bias. Physical input is optional and is only as trustworthy as the object and the recording process.

What is BIP39?

BIP39 standardizes mnemonics drawn from a 2,048-word list with a checksum. Twelve words encode 128 entropy bits plus 4 checksum bits; twenty-four encode 256 plus 8. Import compatibility varies with passphrases, derivation paths, script types, and wallet behavior. Confirm compatibility yourself before relying on an import.

Why run this offline?

Remote dependencies, injected scripts, browser extensions, malware, clipboard monitoring, and screen capture can expose secrets. One inspectable local file with no network requests reduces some attack surfaces, but cannot make compromised hardware, an operating system, or a browser safe.

Can I import the words elsewhere?

Many Bitcoin wallets support BIP39 import, but behavior varies. Entering words into software or an internet-connected device can expose them. Test compatibility with disposable test mnemonics and consult the target wallet's own documentation.

Exact entropy construction

Each part is framed with explicit byte lengths. The system component is SHA-256 over the domain EntropyRacer-v1-system and a fresh 256-bit WebCrypto value. The game and optional physical transcripts are independently hashed under their own domains. Those three 32-byte digests are hashed under EntropyRacer-v1-final, then a length-specific EntropyRacer-v1-bip39-12 or -24 derivation produces the required entropy bytes. The BIP39 checksum is computed and validated before display.

Threat model: what it can help with

The design reduces dependence on one randomness source, remote libraries, server-side generation, network APIs, and silent server storage. It uses fresh session randomness, explicit source separation, local test vectors, and a single-use generation state.

Threat model: what it cannot stop

It cannot protect against a compromised OS, malicious browser or extension, keylogger, screen recorder, compromised hardware, hostile modified copy, weak physical source, exposed words, bad backups, coercion, or unknown future cryptographic weaknesses.

Why open source?

Cryptographic software should be inspectable. Review the complete source and security policy at github.com/Chepenik/entropyracer. A published file is not automatically trustworthy: verify it against the repository or a release hash when one is available.

Recommended offline workflow
  1. Visit and review the GitHub repository.
  2. Obtain the published HTML and verify its release hash if available.
  3. Save the file locally.
  4. Disconnect networking.
  5. Open the local file.
  6. Generate and physically record the mnemonic.
  7. Verify the backup, then destroy the on-screen seed.
  8. Reconnect only after the sensitive session is complete.

Established hardware-wallet workflows are generally preferable for meaningful holdings.
